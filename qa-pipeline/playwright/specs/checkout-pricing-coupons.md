# Checkout pricing and coupons (cart → checkout → order) (frontend)

Scenario input for Module 2. **Generated by hand**, not by `playwright-test-generator` over MCP
— see `pipeline/README.md`'s "The hand-authoring fallback". Two independent reasons apply here:
the single `playwright-test` MCP server's cwd is pinned to the admin panel, and the Generator
agent drives a live browser while generating, which on this feature would place real test
orders and burn the single-use test coupons this plan depends on.

Seed for every scenario: `qa-pipeline/playwright/specs/seed.spec.ts`

## Checkout pricing and coupons — happy path
### Price a configuration, build a 3-line cart, coupon it, and pay COD
**Steps:**
1. Sign in with email + password (the phone tab is Firebase-only in dev) — target: `#email-address` / `#password`, button 'Sign In' (step_id: hp-01)
2. Open the Matte Finish Business Cards PDP and read the default price — target: price summary containing 'GST and shipping calculated at checkout' (step_id: hp-02)
3. Switch size to '2.5 x 2.5 in (Square)' (x1.1) (step_id: hp-03)
4. Stack '350 GSM Matte', 'UV Coating', 'Double Sided' (step_id: hp-04)
5. Reset to defaults and pick the 'Express' turnaround (+₹150) (step_id: hp-05)
6. Type 249 then 250 in the quantity field — target: `input[aria-label='Quantity']` (step_id: hp-06)
7. Add 250 standard business cards to the cart (step_id: hp-07)
8. Add Custom Die-Cut Stickers 100 pcs and A5 Flyers 250 pcs Express (step_id: hp-08)
9. Read the /cart order summary (step_id: hp-09)
10. Apply QA-CHECKOUT-PCT10 (step_id: hp-10)
11. Proceed to checkout and continue with the saved address (step_id: hp-11)
12. Choose Cash on Delivery and review (step_id: hp-12)
13. Compare every figure in 'Price Breakdown' with the server preview (step_id: hp-13)
14. Place the order (step_id: hp-14)
15. Read the confirmation totals (step_id: hp-15)
16. Re-read the same order in account history (step_id: hp-16)

**Expect:** ₹9.00/pc → ₹2,250.00 at 250 with a struck ₹10.00 and 10% off; ₹9.90/pc at the square
size; ₹19.82/pc = ₹4,955.00 with every upgrade; ₹2,400.00 with Express; ₹3,137.40 at 249 and
₹2,250.00 at 250; cart subtotal ₹4,450.00, GST ₹678.81, free shipping; coupon −₹445.00 → total
₹4,005.00, GST ₹610.93, savings ₹695.00; review equals the preview with no 'Prices have been
updated' banner; confirmation and order history repeat the same figures.

## Checkout pricing and coupons — error paths
### Every coupon rejection and acceptance boundary shows the right message and the right total
**Steps:**
1. Unknown code QA-CHECKOUT-NOPE (step_id: err-01)
2. Deactivated coupon QA-CHECKOUT-OFF (step_id: err-02)
3. Expired coupon QA-CHECKOUT-EXPIRED (step_id: err-03)
4. Not-yet-valid coupon QA-CHECKOUT-FUTURE (step_id: err-04)
5. Minimum not met: QA-CHECKOUT-MIN3000 on ₹1,000.00 (step_id: err-05)
6. Minimum met exactly: QA-CHECKOUT-MINEXACT on ₹1,000.00 (step_id: err-06)
7. Max-discount cap: QA-CHECKOUT-CAP50 (step_id: err-07)
8. Excludes discounted items: QA-CHECKOUT-NODISC on a mixed cart (step_id: err-08)
9. Global usage limit reached: QA-CHECKOUT-ONCE (step_id: err-09)
10. Per-user limit reached: QA-CHECKOUT-PERUSER (step_id: err-10)
11. Remove an applied coupon (step_id: err-11)
12. Coupon that no longer qualifies once the cart shrinks (step_id: err-12)

**Expect:** 'Invalid or inactive coupon code', 'Coupon has expired', 'Coupon is not active yet',
'Minimum order amount is ₹3000.00'; MINEXACT applies at equality (−₹100.00, shipping returns,
total ₹999.00); CAP50 gives −₹100.00 not −₹500.00; NODISC discounts only the ₹2,200.00 of
full-price lines (−₹440.00); ONCE and PERUSER report their limits in distinct wording; removing
a coupon restores the uncoupled totals.

## Checkout pricing and coupons — edge cases
### A price edited in admin mid-checkout must not charge the old total
**Steps:**
1. Reach the review step with a server-confirmed preview (step_id: edge-01)
2. Change the product's tier price in the admin API while the customer sits on review (step_id: edge-02)
3. Press Place Order with the stale expectedTotal (step_id: edge-03)
4. Read the re-previewed total and place the order again (step_id: edge-04)

**Expect:** the first attempt is refused with 409 price_changed and creates no order; the banner
'Prices have been updated' appears with 'Prices changed while you were checking out. Nothing has
been charged.'; the breakdown shows the new server total; the second attempt succeeds at the new
price.

## Not generated — unvalidated edge cases
- **Coupon restricted to products/categories is never enforced** (`applicable_product_ids`): no
  code reads the column, so a test asserting enforcement would fail against intended-but-absent
  behaviour. Verified at API level instead and reported as a finding/decision.
- **A coupon that stops qualifying after the cart changes is never re-validated client-side**:
  `features/cart/store.ts` only comments that it should be. err-12 asserts what the code
  actually does today, and the gap is reported rather than tested as a pass.
- **MRP charged outside an inactive discount window**: needs a product whose window has closed;
  exercised outside the browser against a temporarily back-dated window on a product that is
  then restored, because no dev product ships in that state.
- **Invoice PDF** (`GET /orders/{id}/receipt`): reachable from account order detail as 'Receipt
  PDF'; its contents can only be checked outside the browser (WeasyPrint output).
